Privacy Policy

  • Effective 16 August 2026

The short version. Crimstone stores the smallest amount of Discord data it needs to run its features — mainly IDs and counters. It does not keep your message content, it is never sold or handed to advertisers, and you can have everything about you deleted by asking.

The rest of this page spells out exactly what that means. If anything here is unclear, ask before you invite the bot.

Who runs Crimstone

Crimstone is a Discord bot built and operated by Ruby V, trading as AubergineUX, an independent developer based in the United States. There is no company behind it and no team — one person maintains the code, the host, and the data.

This policy covers the bot and this website. It does not cover Discord, which has its own privacy policy, or any other service you reach through a link.

What Crimstone stores

Crimstone stores data in two situations: when a server adds it, and when someone uses a feature that has to remember something. Everything it keeps is listed below.

Server records

Created when Crimstone joins a server, so it knows how that server has configured it.

{ "guildId": "000000000000000000", // which server "prefix": "!", // set by an admin "channels": { ... }, // e.g. where level-ups are announced "roles": { ... }, // e.g. level reward roles "enabled": { ... } // which features are switched on }

Set by server administrators. No personal information beyond Discord IDs.

Member records

Created the first time you trigger a feature that tracks progress, such as earning XP.

{ "userId": "000000000000000000", // your Discord ID "guildId": "000000000000000000", // scoped per server "xp": 0, // a number, not your messages "level": 0, "lastMessage": 0 // timestamp, for XP cooldown only }

Your XP is calculated from the fact that you sent a message, not from what the message said.

Moderation records

When a moderator uses a command such as /ban, Crimstone stores the target user's ID, the moderator's ID, the server ID, the action taken, the reason given, and a timestamp. This is how servers keep a usable moderation history.

Command input

When a command needs text to work — a reason, a tag, a nickname, anything you type into a slash command option — that text is stored so the feature can do its job. Only supply information you are comfortable having saved.

Errors and logs

When something breaks, Crimstone writes a short technical log so the fault can be found. Logs can include your user ID, the server ID, the command name, and the error itself. They are kept no longer than 30 days and are used only for fixing bugs.

What Crimstone never stores

  • The content of your messages. Message events are read in memory to award XP and to detect commands, then discarded — they are not written to disk.
  • Direct messages between you and anyone else.
  • Voice audio, attachments, images, or files.
  • Your email address, phone number, real name, or address.
  • Payment details. Crimstone takes no payments.
  • Your IP address or device information.
  • Anything at all from servers Crimstone has not been invited to.

Why it is stored

  • To make features work. A leveling system cannot show your level without recording it.
  • To respect server settings. Configuration has to persist between restarts.
  • To give moderators a history. Past actions need to stay visible to the staff of that server.
  • To prevent abuse. Cooldown timestamps stop XP farming and command spam.
  • To fix problems. Error logs make bugs reproducible.

Data is never used for advertising, profiling, training machine learning models, or anything unrelated to running the bot.

Where and how it is stored

Crimstone's data lives on a server rented from [hosting provider], located in [country]. Records are held in structured files on that server. If you use Crimstone from outside that country, your data is processed there.

Access is limited to the bot operator, over authenticated connections. Backups are kept for [7 days] and are overwritten on a rolling basis.

Reasonable steps are taken to keep this data secure, but no service can promise perfect security. Treat Crimstone the way you would treat any small self-hosted project: do not put sensitive information into it. If a breach affects your data, notice will be posted in the support server and on this site as quickly as the facts allow.

How long it is kept

  • Server records are deleted within 30 days of Crimstone being removed from that server.
  • Member records are kept while you remain in a server that uses Crimstone, and are deleted on request at any time.
  • Moderation records are kept while the bot remains in that server, since they belong to the server's staff.
  • Command input is deleted when the thing it belongs to is deleted.
  • Logs are rotated out after 30 days.

Who else sees it

Crimstone's data is not sold, rented, or traded. It is shared only in these cases:

  • Discord — everything the bot does travels over Discord's API, because that is how bots work.
  • The hosting provider — as the operator of the machine the data sits on.
  • Your server's moderators — moderation history is visible to the staff of the server it happened in.
  • Other members of your server — leaderboards, level-up messages, and rank commands are public by design. Anything visible in a channel is visible to whoever can read that channel.
  • Bot listing sites such as top.gg receive only totals, such as server count. No individual data is sent.
  • The law — if a valid legal request requires disclosure.

Your choices

You can ask for a copy of everything Crimstone holds about you, ask for it to be corrected, or ask for it to be deleted. There is no charge and you do not need to give a reason.

  • Run /data export to receive your records.
  • Run /data delete to erase them.
  • Or contact the operator using the details below.

Requests are handled within 30 days. Deletion is permanent — XP and levels cannot be restored afterwards. Note that continuing to use tracked features will start building a new record.

Depending on where you live you may have additional rights, including under the UK and EU GDPR and the California Consumer Privacy Act. Those rights are honoured regardless of where you are. Where the GDPR applies, the lawful basis for this processing is legitimate interest: operating a bot that a server has chosen to install.

If you run a server

Inviting Crimstone means you are asking it to process data about your members. Please make sure your members know it is there, keep the permissions granted to the minimum the features need, and remove the bot if you no longer want that processing to happen. Any settings you configure are your responsibility.

Age

Discord requires users to be at least 13, or older where local law sets a higher minimum. Crimstone is not intended for anyone below that age and does not knowingly store their data. If you believe a child's data has been stored, get in touch and it will be removed.

Changes to this policy

This policy will change as Crimstone changes. The effective date at the top always reflects the current version. Significant changes will be announced in the support server before they take effect. Continuing to use the bot after that means you accept the updated policy.
